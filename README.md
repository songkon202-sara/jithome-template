# JitHome — ระบบติดตามผู้ป่วยจิตเวชในชุมชน (ชุดติดตั้งสำหรับ รพ.สต.)

ระบบสำหรับเจ้าหน้าที่ รพ.สต. และ อสม. ใช้ติดตามผู้ป่วยจิตเวช: นัดฉีดยา นัดพบแพทย์ เยี่ยมบ้าน
แบบประเมิน (2Q+, OAS, ติดตาม 10 ด้าน) ส่งต่อ รพ. แม่ข่าย และแจ้งเตือนผ่าน LINE / Telegram

แต่ละหน่วยงาน **ติดตั้งและดูแลระบบของตัวเอง** ด้วยบัญชี GitHub และ Supabase ของหน่วยงาน
ข้อมูลผู้ป่วยของแต่ละแห่งแยกขาดจากกัน หน่วยงานอื่นเข้าถึงไม่ได้

> ⚠️ **ข้อมูลผู้ป่วยจิตเวชเป็นข้อมูลอ่อนไหวตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล (PDPA)**
> ก่อนใช้งานจริง ควรปรึกษาเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) ของหน่วยงานหรือ สสจ.
> และ **ห้ามนำไฟล์ข้อมูลผู้ป่วยใส่ไว้ใน repo** (repo เป็น public ทุกคนเปิดอ่านได้)

## ขั้นตอนติดตั้ง

### 1. สร้างฐานข้อมูล (Supabase)

1. เข้า [supabase.com](https://supabase.com) → **New project**
   - ตั้งชื่อ เช่น `jithome-<ชื่อตำบล>` · Region: **Southeast Asia (Singapore)**
   - ตั้งรหัสผ่านฐานข้อมูลแล้ว**จดเก็บไว้**
2. รอสร้างเสร็จ (1–2 นาที) → เมนูซ้าย **SQL Editor** → **New query**
3. เปิดไฟล์ [`sql/install.sql`](sql/install.sql) → คัดลอกทั้งหมด → วาง → **Run**
   - ถ้ามีหน้าต่างเตือน *Potential issue detected* ให้กด **Run without RLS** (สคริปต์เปิด RLS ให้เองครบทุกตาราง)
   - ผลที่ควรเห็นท้ายสุด: `ติดตั้งเสร็จ`
   - ถ้าขึ้น `ยังไม่ครบ: pg_net` หรือ `pg_cron` → เมนู **Database → Extensions** → ค้นหาชื่อนั้น → เปิด → กลับมารัน install.sql อีกครั้ง (รันซ้ำได้ ไม่ลบข้อมูล)
4. ตั้งค่าการเข้าสู่ระบบ: **Authentication → Sign In / Providers → Email** → ปิด **Confirm email**
   (อสม. สมัครด้วยเบอร์โทร ไม่มีอีเมลจริง)
5. เปิด 2FA: **Authentication → Multi-Factor** → เปิด **TOTP**
6. จด 2 ค่านี้ไว้ใช้ขั้นที่ 3 จาก **Project Settings → API**
   - **Project URL** เช่น `https://abcdefghijkl.supabase.co`
   - **anon public** key (ขึ้นต้น `eyJ...`) หรือ **publishable** key (ขึ้นต้น `sb_publishable_...`)
   - ⚠️ **ห้ามใช้ `service_role` / `secret` key** กับเว็บในขั้นตอนใดเลย

### 2. ติดตั้งฟังก์ชันแจ้งเตือน (Edge Functions)

Supabase → **Edge Functions → Deploy a new function → Via Editor** ทีละตัว
ลบโค้ดตัวอย่างออกก่อน แล้ววางโค้ดจากไฟล์ใน repo · ตั้งชื่อให้ตรงตัว · เปิด **Verify JWT** ไว้ตามค่าเริ่มต้น

| ชื่อฟังก์ชัน | วางโค้ดจาก | ใช้ทำอะไร |
|---|---|---|
| `notify` | [`supabase/functions/notify/index.ts`](supabase/functions/notify/index.ts) | ส่ง LINE / Telegram จากแอป |
| `reset-aosomo-password` | [`supabase/functions/reset-aosomo-password/index.ts`](supabase/functions/reset-aosomo-password/index.ts) | แอดมินรีเซ็ตรหัสผ่าน อสม. |

ถ้าใช้ Supabase CLI ได้: `supabase functions deploy notify` และ `supabase functions deploy reset-aosomo-password`

### 3. สร้างเว็บ (GitHub)

1. กดปุ่ม **Use this template → Create a new repository** ด้านบนของหน้านี้
   - ตั้งชื่อ repo เช่น `jithome` · เลือก **Public** (GitHub Pages แบบฟรีต้องเป็น public)
2. ใน repo ใหม่ เปิดไฟล์ **`config.js`** → กดรูปดินสอ (Edit) → แก้ค่า:
   ```js
   SUPABASE_URL: 'https://abcdefghijkl.supabase.co',   // จากขั้นที่ 1.6
   SUPABASE_ANON_KEY: 'eyJ...',                          // anon / publishable key
   HOSPITAL_NAME: 'รพ.สต.บ้านตัวอย่าง',
   VILLAGES: ['หมู่ 1', 'หมู่ 2', 'หมู่ 3', 'นอกเขต'],
   ```
   → **Commit changes**
3. **Settings → Pages** → Source: **Deploy from a branch** → Branch: **main** / **(root)** → **Save**
4. รอ 1–2 นาที เว็บจะอยู่ที่ `https://<ชื่อบัญชี GitHub>.github.io/<ชื่อ repo>/`

### 4. ผูกเว็บกับฐานข้อมูล

Supabase → **Authentication → URL Configuration**
- **Site URL** = ที่อยู่เว็บจากขั้นที่ 3.4
- **Redirect URLs** → เพิ่มที่อยู่เดียวกัน (ใช้กับลิงก์ "ลืมรหัสผ่าน")

### 5. สร้างบัญชีผู้ดูแลระบบคนแรก

1. เปิดเว็บ → **สมัครสมาชิก** ด้วยอีเมลของผู้ดูแลระบบ — **บัญชีแรกของระบบเป็นแอดมินอัตโนมัติ**
2. เข้าสู่ระบบ → ระบบจะให้ตั้ง 2FA ด้วยแอป Google Authenticator / Authy
3. หน้า **แอดมิน** → ตั้งชื่อหน่วยงาน, LINE, Telegram (ถ้าใช้)

> ทำขั้นนี้**ทันที**หลังเปิดเว็บ ถ้าคนอื่นสมัครก่อน คนนั้นจะได้เป็นแอดมิน
> ผู้ที่สมัครหลังจากนี้ทุกคนต้องรอแอดมินอนุมัติ

### 6. เริ่มใช้งาน

- **ตั้งผู้รับแจ้งเหตุข้อมูลรั่วไหล (PDPA):** หน้าแอดมิน → ช่อง "ผู้รับแจ้งเหตุข้อมูลรั่วไหล"
  ใส่ชื่อ ตำแหน่ง เบอร์โทร เช่น `นายสมชาย ใจดี พยาบาลวิชาชีพ โทร 08x-xxx-xxxx` → บันทึก
  ชื่อนี้จะแสดงในข้อตกลงรักษาความลับที่ผู้ใช้ทุกคนต้องกดยอมรับก่อนดูข้อมูลผู้ป่วย
- **นำเข้ารายชื่อผู้ป่วย:** หน้าแอดมิน → นำเข้าไฟล์ (Excel / CSV / HOSxP) มีปุ่มดาวน์โหลดไฟล์ตัวอย่าง
- **เพิ่ม อสม.:** หน้าแอดมิน → สร้างบัญชี อสม. (ใช้เบอร์โทรเป็นชื่อผู้ใช้) หรือให้ อสม. สมัครเองแล้วอนุมัติ
- **ติดตั้งบนมือถือ:** เปิดเว็บใน Chrome / Safari → เมนู → **เพิ่มลงหน้าจอหลัก**

## การแจ้งเตือน (ไม่บังคับ)

| ช่องทาง | ตั้งค่าที่ | ส่งอะไร |
|---|---|---|
| LINE (Messaging API) | หน้าแอดมิน → LINE: Channel access token + Group ID | รายงานเยี่ยมบ้าน |
| Telegram | หน้าแอดมิน → Telegram: Bot Token (จาก @BotFather) + Chat ID | รายงานผู้เกินนัดและนัดพรุ่งนี้ ทุกวัน 07:00 น. (ตั้งเวลาให้แล้วใน install.sql) |
| ส่งต่อ รพ. แม่ข่าย | หน้าแอดมิน → ส่งต่อ รพ. แม่ข่าย | ใบส่งต่อเมื่อติ๊ก "ส่งต่อ" ในการเยี่ยมบ้าน |

token ทุกตัวเก็บในฐานข้อมูลฝั่งเซิร์ฟเวอร์ ไม่ถูกส่งไปที่เบราว์เซอร์ของผู้ใช้

> ⚠️ ข้อความแจ้งเตือนมี**ชื่อผู้ป่วยเต็ม** — กลุ่ม LINE / Telegram ต้องมี**เฉพาะเจ้าหน้าที่**เท่านั้น ตรวจสมาชิกกลุ่มสม่ำเสมอ

## สิทธิ์ของแต่ละบทบาท

| บทบาท | ดูผู้ป่วย | บันทึก/แก้ไข | ลบ | ตั้งค่าระบบ / จัดการสมาชิก |
|---|---|---|---|---|
| แอดมิน (ต้องใช้ 2FA) | ✅ | ✅ | ✅ | ✅ |
| เจ้าหน้าที่ (ต้องใช้ 2FA) | ✅ | ✅ | ✅ | — |
| อสม. | เฉพาะหมู่บ้านของตัวเอง | ✅ | เฉพาะบันทึกเยี่ยมบ้าน | — |
| ผู้สังเกตการณ์ | หน้าภาพรวม | — | — | — |
| รออนุมัติ / ถูกระงับ | — | — | — | — |

สิทธิ์ถูกบังคับที่ฐานข้อมูล (Row Level Security) ไม่ใช่แค่ซ่อนปุ่มบนหน้าจอ

- ผู้ใช้ทุกคนต้องกดยอมรับ**ข้อตกลงรักษาความลับ**ทุกครั้งที่เข้าใช้งาน ระบบบันทึกเวลาที่ยอมรับไว้เป็นหลักฐาน
- อสม. ต้องกำหนดหมู่บ้านให้ตรงกับชื่อหมู่บ้านในทะเบียนผู้ป่วย (ถ้ายังไม่กำหนด จะเห็นผู้ป่วยทุกหมู่บ้าน)
- แอดมินระงับ / เปิดใช้งานบัญชีได้ในหน้าสมาชิก (ปุ่ม ⏸️ ระงับ)
- ใส่รหัสผ่านผิด 5 ครั้ง บัญชีถูกล็อก 15 นาที

## ตรวจความปลอดภัยหลังติดตั้ง

เปิดลิงก์นี้ในเบราว์เซอร์ (แทนค่าของหน่วยงาน) ต้องได้ข้อความ `permission denied`:

```
https://<PROJECT>.supabase.co/rest/v1/patients?select=id&limit=1&apikey=<ANON_KEY>
```

ถ้าได้รายการข้อมูลกลับมา แปลว่าติดตั้ง `install.sql` ไม่ครบ **หยุดใช้งานและรันใหม่**

## อัปเดตเวอร์ชันใหม่

เมื่อ repo ต้นแบบมีเวอร์ชันใหม่ ให้คัดลอกไฟล์ `app.js`, `index.html`, `style.css`, `sw.js`
ไปทับใน repo ของหน่วยงาน (**ไม่ต้องทับ `config.js`**) และรันไฟล์ใน `sql/upgrades/` (ถ้ามี) ตามลำดับ

## หมายเหตุเรื่องค่าใช้จ่าย

แผนฟรีของ Supabase เพียงพอสำหรับ รพ.สต. หนึ่งแห่ง แต่มีข้อจำกัด เช่น project ถูกพักชั่วคราว
เมื่อไม่มีการใช้งานต่อเนื่องราว 1 สัปดาห์ และจำนวน project ฟรีต่อบัญชีมีจำกัด
ตรวจรายละเอียดล่าสุดที่ [supabase.com/pricing](https://supabase.com/pricing) ก่อนตัดสินใจ

## โครงสร้างไฟล์

```
config.js                 ← ไฟล์เดียวที่แต่ละหน่วยงานแก้
index.html  app.js  style.css  sw.js  manifest.json  icon.svg   ← ตัวเว็บ (ไม่ต้องแก้)
sql/install.sql           ← สร้างฐานข้อมูลครบในครั้งเดียว
supabase/functions/       ← Edge Functions: notify, reset-aosomo-password
```
